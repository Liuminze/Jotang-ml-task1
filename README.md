```bash
pip install -r requirements.txt
python mlp_make_moons.py
```

## 3. 结果

- 模型 `2 → 64 → 2`，ReLU，参数量 **322**（fc1：2×64+64=192，fc2：64×2+2=130，别漏 bias）
- Adam，lr=1e-3，batch 32，60 epoch
- 验证集最高 **0.940**，测试集 **0.975**，200 条里判错 5 条
- 混淆矩阵 `[[97, 3], [2, 98]]` —— 两类错得差不多，没有偏向哪一边
- 存的是**验证集最高那一次**的权重，不是最后一轮

判错的 5 个点（`figure_07.png` 里黑圈标出来的）基本都落在两条月牙交界的重叠带上。`noise=0.2`
让两类点在天生模糊的区域互相渗透，我觉得这不是模型的 bug，而是这份数据本身的"不可约错误"——
想降只能减小 noise（等于换数据），继续调参没用。

## 4. 两组对照实验

**因素一：隐藏层宽度**（其他都不动）

| hidden_dim | 参数量  | 验证最高 acc | 我的观察                    |
| ----------:| ----:| --------:| ----------------------- |
| 8          | 90   | 0.850    | 太窄，弯不出月牙的边界，欠拟合         |
| 64         | 322  | 0.940    | 够用                      |
| 256        | 1314 | 0.960    | 只高了 0.02，参数量翻 4 倍，训练还慢了 |

**因素二：学习率**（hidden_dim 固定 64）

| lr   | 验证最高 acc | 我的观察                  |
| ----:| --------:| --------------------- |
| 1e-2 | 0.975    | 收敛最快，而且更好（这点后面我要认个错）  |

## 5. 我自己踩过的坑

这段是我真实卡住的地方，不是从教程上抄的：

1. **NameError 连着报了三次**：`model`、`np`、`val_loader` 一个个未定义。原因是我跳着格子跑，
   前面的没执行，后面的名字自然不存在。后来养成习惯：改完就 Restart Kernel and Run All 从头跑一遍。
   更蠢的一次是我把「Kernel → Restart Kernel and Run All Cells」这行**菜单路径当成 Python 敲进了格子**，
   报 `SyntaxError: invalid character '→' (U+2192)`。教训：对话里只有代码块里的东西能敲，
   菜单路径、表格都是给人看的；Python 源码只认 ASCII，中文箭头这种字符只能放在字符串和注释里。

2. **标准化差点做错**：一开始我想"全部数据一起标准化多省事"，后来意识到这是偷看答案 ——
   验证集和测试集是"将来的数据"，不该用它们的均值和方差。正确做法是 scaler 只在训练集上 `fit`，
   再 `transform` 到另外两份。这个坑最阴，因为它不报错，错了你根本发现不了，分数只是虚高。

3. **存哪一轮**：一开始我存最后一轮，后来发现最后一轮常常已经开始背训练集了（train 还在涨，val 掉头）。
   改成"验证集最高那次"之后测试更稳。

## 6. 一个我自己发现的矛盾，贴出来不藏

上面那张 lr 表里，`1e-2`（0.975）明明比 `1e-3`（0.940）好，但我最终交的模型用的是 `1e-3`。
原因很朴素：**1e-3 是我最开始跑通的那版**，对照实验是之后才做的，做完我没回头改主模型。

我觉得藏着这个更丢人，所以单独写了个 `check_lr.py` 复查（同种子、同划分，把两个 lr 都拿到测试集上比一次）：

| lr   | 验证最高  | 测试    | 最后 10 轮验证准确率波动 |
| ----:| -----:| -----:| --------------:|
| 1e-2 | 0.985 | 0.985 | 0.002          |
| 3e-3 | 0.985 | 0.970 | 0.004          |
| 1e-3 | 0.970 | 0.970 | 0.005          |
| 1e-5 | 0.805 | 0.850 | 0.008          |

结论：**1e-2 确实更好，而且更稳**（后期波动更小）。按规矩应该拿验证集选 1e-2，
主模型用 1e-3 是我偷懒，不是实验结论。要是重做，我会用 1e-2。

（这表里 1e-3 那行 0.970/0.970 和主实验的 0.940/0.975 差了零点零几，是因为脚本里模型初始化的时机
和 notebook 不完全一样，属正常抖动，不影响方向。跑 `python check_lr.py` 可以复现这张表。）

## 7. 思考题（趁热打铁）

下面的深浅不一，我不确定的地方都标了，别当成标准答案看。

**① 激活函数选了什么，为什么？**

用的 ReLU，`max(0, x)`。我一开始不理解为什么要加这一层，后来想通了一个粗糙的说法：没有它，
两层线性变换叠起来还是一次线性变换，只能画直线，而月亮是弯的。至于"梯度消失"那套推导我讲不深，
我目前只能说到这一层：ReLU 正区间梯度恒为 1，Sigmoid 最大才 0.25，层数一多连乘就小到没法更新。
还有个坑我是看别人笔记看到的、自己没遇到：lr 太大时神经元会"死掉"（输出恒为 0，梯度也恒为 0）。

**② 损失函数？三分类怎么办？**

`nn.CrossEntropyLoss`，多分类标配。它内部自带 LogSoftmax，所以输出层**不要再加 Softmax** ——
这条我是在文档里看到的，不是踩坑踩出来的。三分类就把最后一层改成 `nn.Linear(hidden, 3)`、
标签变 0/1/2，损失函数一个字都不用动，这也是选它的原因。

**③ zero_grad / backward / step 各干什么？不清零会怎样？**

- `zero_grad()`：把参数的 `.grad` 清零。PyTorch 梯度默认是**累加**的（accumulate，为梯度累积设计的），
  所以每个 batch 前必须清。
- `backward()`：沿计算图反着算每个参数的梯度，结果写进 `param.grad`。
- `step()`：优化器按梯度更新参数（Adam 还叠了动量和自适应步长）。

不清零的话，本 batch 的梯度 = 之前所有 batch 梯度之和，方向乱、步长越滚越大，loss 不降反升。
这个我没敢乱试（怕真跑飞），是逻辑推的。

**④ 更深更宽一定更好吗？**

不一定，我自己的实验就是证据：8 → 0.850（太窄，欠拟合），64 → 0.940，256 → 0.960。
256 比 64 只高 0.02，参数量却翻了 4 倍，训练也慢了。我的理解是"够用就行，再大就是在背训练点"。
这题我讲不出理论（没学线代，也没学泛化误差那套），只能拿数据说话。

**⑤ 学习率过大/过小的影响？loss 曲线上能看出什么？**

太大 → 在最优点两边来回跳，loss 剧烈抖动甚至 NaN；太小 → 根本走不到，
我这个 1e-5 跑 60 轮才 0.820，曲线几乎是条水平线。合适的曲线是"平滑下降然后走平"。
顺带一提，Adam 从 1e-3 起步是经验值，但这次数据告诉我 1e-2 更好（见第 6 节）。

**⑥ 两个类别样本数极不均衡会怎样？**

比如 950:50，模型会偏向多数类 —— 全猜多数类就有 95% 准确率，但少数类召回接近 0。
原因是总损失被多数类的梯度主导。所以这时候**准确率是骗人的**，得看混淆矩阵、precision、recall、F1。
这一条我没真跑（题面没要求），是推理出来的。改法我了解到三种：class weight、过采样、欠采样。

**⑦ 想故意过拟合一个数据集，怎么做？怎么判断？**

三招凑齐必过拟合：训练集砍到极少（比如 20 个点）+ 网络加宽（256+）+ 几百个 epoch 且去掉早停。
现象是 train 准确率直奔 1.0 而 val 停滞，val 的 loss 先降后升呈 U 型，决策边界会从平滑曲线
变成围着每个训练点的一堆"小岛"。**判断核心：train 和 val 出现分叉就是过拟合的直接证据。**
这也是我为什么存验证集最高那次权重而不是最后一轮。
